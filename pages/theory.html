Chapter 1: Introduction to C

1.1 Definition — What is C?

C is a general-purpose, procedural, statically-typed, compiled programming language. "Procedural" means a C program is built from a sequence of instructions organized into functions; "statically-typed" means every variable's type is fixed at compile time; "compiled" means source code is translated into machine code by a compiler before the program runs, rather than being interpreted line-by-line.

1.2 History of C

  • 1969–1973: Dennis Ritchie developed C at Bell Labs, evolving it from an earlier language called B (itself derived from BCPL).
  • Purpose at creation: C was built to rewrite the UNIX operating system, which had originally been written in assembly language. This is why C gives programmers low-level control (like assembly) while still being readable (like a high-level language).
  • 1978: Brian Kernighan and Dennis Ritchie published The C Programming Language, which became the de facto specification until an official standard existed.
  • 1989/1990: The language was standardized as ANSI C / C89 (and ISO C90 internationally).
  • Later standards: C99, C11, C17, C23 each added features (like // comments, bool, variable-length arrays, improved Unicode support) while preserving backward compatibility.

📝 Note: C is often called the "mother language" of programming because compilers/interpreters for many later languages (C++, Java, Python's CPython, PHP, Perl) were themselves written in C, and those languages borrowed C's syntax.

1.3 Purpose — Why C Exists

Before C, systems programmers had to choose between:

  • Assembly language — fast and gives full hardware control, but unreadable, error-prone, and not portable between CPU architectures.
  • High-level languages of the time — easier to read, but too slow and too abstracted from hardware for operating-system work.

C was designed to sit in the middle: close enough to hardware to manipulate memory directly (via pointers), yet with structured, readable syntax. This is why C is called a middle-level language.

1.4 Features of C

Feature What it means
Simplicity Small set of keywords (32 in the original standard)
Portability The same C source compiles on different machines/OSes with little or no change
Speed Compiles directly to native machine code — no interpreter overhead
Structured Code is organized into functions and blocks, not just jumps
Low-level access Pointers let you read/write memory addresses directly
Rich operator set Bitwise, logical, arithmetic, relational operators built in
Extensible New functionality is added via libraries, not new language syntax
Recursion Functions can call themselves

1.5 Advantages of C

  • Extremely fast execution — close to hardware, minimal runtime overhead.
  • Full manual control over memory (allocate/free exactly what you need).
  • Forms the foundation for learning virtually every other language's concepts.
  • Huge legacy codebase and library ecosystem (most OS-level APIs are exposed as C functions).
  • Portable across architectures with a standards-compliant compiler.

1.6 Disadvantages of C

  • No built-in object-oriented support (no classes, inheritance, etc.).
  • No automatic memory management — the programmer must free everything manually, which is a major source of bugs (memory leaks, dangling pointers).
  • No built-in exception handling — errors are typically reported through return codes.
  • No bounds checking on arrays — writing past the end of an array is legal C (and dangerous).
  • Weaker standard library than modern languages (no built-in dynamic string type, hash maps, etc.).

1.7 Applications of C

  • Operating systems: The Linux kernel, large parts of Windows, and macOS/iOS's XNU kernel are written in C.
  • Embedded systems & IoT: Microcontroller firmware (Arduino's core libraries are C/C++).
  • Databases: The cores of MySQL, PostgreSQL, SQLite are written in C.
  • Language runtimes: CPython (the standard Python interpreter) and parts of the JVM are implemented in C.
  • Device drivers, compilers, and network stacks.

1.8 Structure of a C Program

Every C program follows the same skeleton:

[Preprocessor Directives]      // e.g. #include, #define
[Global Declarations]          // global variables, function prototypes

int main(void) {
    [Local Declarations]       // variables used only inside main
    [Statements]                // the actual instructions
    return 0;                   // exit status to the operating system
}

[User-Defined Functions]        // other functions, if any

Step-by-step: the "Hello, World!" program

#include <stdio.h>

int main(void) {
    printf("Hello, World!\n");
    return 0;
}

Output:

Hello, World!

Line by line:

  1. #include <stdio.h> — a preprocessor directive. Before compilation, this line is replaced with the contents of the Standard Input/Output header file, which declares printf. Without it, using printf would trigger a compiler error/warning.
  2. int main(void) — every C program must have exactly one main function; it's the entry point the operating system calls to start the program. int means it returns an integer exit status; void means it takes no arguments.
  3. { — opens the function body.
  4. printf("Hello, World!\n"); — a statement: a function call followed by a semicolon. \n is an escape sequence for a newline.
  5. return 0; — sends exit status 0 back to the operating system, which by convention means "the program finished successfully."
  6. } — closes the function body.

Memory representation: how a compiled C program sits in memory

When you run a compiled C program, the operating system loads it into a process with this general layout:

High Address
+-----------------------+
|         Stack          |  <- function calls, local variables (grows downward)
|           |             |
|           v             |
+-----------------------+
|                        |
|     (free space)       |
|                        |
+-----------------------+
|           ^             |
|           |             |
|         Heap            |  <- malloc/calloc/realloc memory (grows upward)
+-----------------------+
|      BSS Segment        |  <- uninitialized global/static variables
+-----------------------+
|      Data Segment       |  <- initialized global/static variables
+-----------------------+
|      Text/Code Segment  |  <- the compiled machine instructions (read-only)
+-----------------------+
Low Address

This model matters throughout C: local variables live on the stack and disappear when a function returns; malloc-ed memory lives on the heap and persists until you free it (Chapter 13); global variables live in the data/BSS segments for the entire life of the program.

1.9 Common Mistakes (Chapter 1)

  • Forgetting the semicolon at the end of a statement.
  • Writing Main or MAIN instead of main — C is case-sensitive.
  • Forgetting #include <stdio.h> and then using printf.
  • Mismatched { } braces, especially in longer programs.
  • Forgetting return 0; (most compilers allow this and assume 0, but it's poor practice to omit it).

1.10 Interview Questions (Chapter 1)

Q1: Why is C called a "middle-level" language? Because it combines low-level features (direct memory access via pointers, bit manipulation) with high-level structured-programming constructs (functions, loops, conditionals).

Q2: Why is C called the "mother language"? Because compilers or interpreters for many later languages (C++, Java's JVM components, Python's CPython, PHP) were themselves written in C, and those languages inherited much of C's syntax.

Q3: What is the difference between a compiler and an interpreter, and which does C use? A compiler translates the entire source file into machine code before execution (producing a standalone executable); an interpreter reads and executes source code line by line at runtime. C uses a compiler.

Q4: Why must every C program have a main() function? Because main is the fixed entry point the operating system's loader calls to begin execution — without it, the OS has no defined place to start running the program.

Q5: What is the difference between C and C++? C is purely procedural with no built-in object-oriented features; C++ is a superset of C that adds classes, objects, inheritance, templates, and exception handling while remaining largely backward-compatible with C syntax.

1.11 Practice Questions (Chapter 1)

  1. Write a C program that prints your name and course on two separate lines using two separate printf statements.
  2. What happens if you remove return 0; from a C program? Try it and observe whether it still compiles.
  3. Name two real-world software systems written in C (other than the ones listed above).
  4. Explain, in your own words, why C programs need to be compiled before they can run.

1.12 Best Practices (Chapter 1)

💡 Tip: Always include return 0; explicitly, even though many compilers infer it.

💡 Tip: Use int main(void) rather than int main() — void explicitly states "no parameters," which avoids ambiguity in older compilers.

  • Write one clear comment above any non-obvious block of code.
  • Keep indentation consistent (most style guides use 4 spaces).
  • Include only the headers you actually use.

Chapter 1 Summary

C is a compiled, procedural, middle-level language created in 1972 to build UNIX. It trades automatic safety nets (garbage collection, bounds checking) for speed and direct memory control, which is why it still underlies most operating systems, databases, and language runtimes today. Every C program follows the same skeleton: preprocessor directives, optional global declarations, a mandatory main() function, and optional user-defined functions.

Chapter 2: Tokens, Keywords, Identifiers, Constants & Variables

2.1 Tokens

Definition: A token is the smallest individual unit in a line of C source code that the compiler recognizes as meaningful — the compiler breaks your entire program down into a stream of tokens before it does anything else.

Types of tokens in C:

  1. Keywords (e.g., int, return)
  2. Identifiers (e.g., age, main)
  3. Constants (e.g., 20, 'A')
  4. String literals (e.g., "Hello")
  5. Operators (e.g., +, =)
  6. Special symbols / punctuators (e.g., {, }, ;, (, ))

Example: the line int age = 20; breaks into 5 tokens: int age = 20 ;

2.2 Keywords

Definition: Keywords are reserved words with a predefined meaning to the compiler. They cannot be used as variable, function, or any other identifier names.

The 32 original C keywords:

auto      break     case      char      const     continue  default   do
double    else      enum      extern    float     for       goto      if
int       long      register  return    short     signed    sizeof    static
struct    switch    typedef   union     unsigned  void      volatile  while

📝 Note: Later standards added more reserved words — C99 added inline, restrict, _Bool, _Complex, _Imaginary; C11 added _Alignas, _Alignof, _Atomic, _Generic, _Noreturn, _Static_assert, _Thread_local.

Rules: always lowercase, cannot be redefined or used as identifiers, each has one fixed grammatical role.

2.3 Identifiers

Definition: An identifier is the name a programmer gives to a variable, function, array, structure, or any other user-defined item.

Naming rules:

  • Must begin with a letter (A–Z, a–z) or an underscore _.
  • Remaining characters may be letters, digits, or underscores.
  • Cannot be a keyword.
  • Case-sensitive: age, Age, and AGE are three different identifiers.
  • No spaces or special characters (@, -, %, etc.) allowed.
Identifier Valid? Reason
age ✅ starts with a letter
_count ✅ starts with underscore
student1 ✅ letters + digit, doesn't start with digit
1student ❌ cannot start with a digit
int ❌ reserved keyword
first-name ❌ hyphen is not allowed
first name ❌ spaces are not allowed

2.4 Constants

Definition: A constant is a value that cannot change during program execution.

Types of constants:

  • Integer constants: 10, -5, 0x1A (hex), 012 (octal)
  • Floating-point constants: 3.14, 2.5e3
  • Character constants: 'A', '9', '\n'
  • String constants: "Hello"
  • Enumeration constants: named integer constants defined with enum (Chapter 14)

Two ways to define a constant in C:

const int MAX_MARKS = 100;   // (1) the const keyword
#define PI 3.14159            // (2) a preprocessor macro
Aspect const #define
Processed by Compiler Preprocessor (before compilation)
Type checking Yes — has a real type No — pure text substitution
Memory Normally allocated None — text is replaced before compiling
Scope Follows normal block/file scope Active everywhere after the #define line
Visible to a debugger Yes No — already substituted away

2.5 Variables

Definition: A variable is a named location in memory that holds a value which can change during program execution.

Declaration vs. initialization:

int age;        // declaration — reserves memory, value is garbage/indeterminate
int age = 20;    // initialization — declaration + an initial value in one step

Purpose: variables let a program store, retrieve, and manipulate data by name instead of by raw memory address.

Memory representation: every variable has an address (where it lives in memory) and a size (how many bytes it occupies, determined by its type). You can view both:

int age = 20;
printf("Value: %d\n", age);
printf("Address: %p\n", (void*)&age);
printf("Size: %zu bytes\n", sizeof(age));

Conceptually, age sits in memory like this (the exact address changes every run — this is illustrative):

Address:  0x7ffee23a1a4c  0x...4d  0x...4e  0x...4f
Bytes:         14h            00h      00h      00h      <- little-endian storage of 20

Naming rules: identical to identifier rules in §2.3.

2.6 Program Examples

Beginner Example 1 — Declaring and printing variables of different types

#include <stdio.h>

int main(void) {
    int age = 20;
    float height = 5.9;
    char grade = 'A';

    printf("Age: %d\n", age);
    printf("Height: %.1f\n", height);
    printf("Grade: %c\n", grade);

    return 0;
}

Output:

Age: 20
Height: 5.9
Grade: A

Line-by-line: three variables of different types are declared and initialized in one line each; each printf uses the format specifier matching its type (%d for int, %.1f for a float rounded to one decimal, %c for a single character). Complexity: O(1) time and space — fixed number of operations regardless of input.

Beginner Example 2 — Multiple declaration and arithmetic

#include <stdio.h>

int main(void) {
    int a = 5, b = 10, sum;
    sum = a + b;
    printf("a = %d, b = %d\n", a, b);
    printf("Sum = %d\n", sum);
    return 0;
}

Output:

a = 5, b = 10
Sum = 15

Line-by-line: a, b, and sum are declared in a single statement (a comma-separated list) to reduce repetition; sum is left uninitialized until it's assigned the result of a + b. Complexity: O(1).

Beginner Example 3 — Swapping two variables with a temporary variable

#include <stdio.h>

int main(void) {
    int x = 10, y = 20, temp;
    printf("Before swap: x = %d, y = %d\n", x, y);
    temp = x;
    x = y;
    y = temp;
    printf("After swap: x = %d, y = %d\n", x, y);
    return 0;
}

Output:

Before swap: x = 10, y = 20
After swap: x = 20, y = 10

Line-by-line: the classic three-step swap — temp holds x's original value so it isn't lost when x is overwritten by y, then y receives what temp saved. Complexity: O(1).

Intermediate Example 1 — const and #define together

#include <stdio.h>
#define PI 3.14159

int main(void) {
    const int MAX_MARKS = 100;
    float radius = 5.0;
    float area;

    area = PI * radius * radius;

    printf("Max marks (const): %d\n", MAX_MARKS);
    printf("PI (macro): %.5f\n", PI);
    printf("Area of circle: %.2f\n", area);

    return 0;
}

Output:

Max marks (const): 100
PI (macro): 3.14159
Area of circle: 78.54

Line-by-line: PI is substituted as literal text by the preprocessor before compilation even starts; MAX_MARKS is a real, typed, compiler-checked constant. Both behave the same for reading, but see §2.4's table for how differently they're processed.

Intermediate Example 2 — the sizeof operator

#include <stdio.h>

int main(void) {
    int i = 10;
    float f = 3.14f;
    double d = 3.14159;
    char c = 'A';

    printf("Size of int: %zu bytes\n", sizeof(i));
    printf("Size of float: %zu bytes\n", sizeof(f));
    printf("Size of double: %zu bytes\n", sizeof(d));
    printf("Size of char: %zu bytes\n", sizeof(c));

    return 0;
}

Output:

Size of int: 4 bytes
Size of float: 4 bytes
Size of double: 8 bytes
Size of char: 1 bytes

Line-by-line: sizeof is a compile-time operator (not a function call) that returns the number of bytes a type/variable occupies; %zu is the correct format specifier for the size_t type it returns. These exact sizes are standard on mainstream 64-bit systems but are not guaranteed by the C standard — always confirm with sizeof rather than hardcoding sizes.

Intermediate Example 3 — Global vs. local variables (preview)

#include <stdio.h>

int globalVar = 100;

void display(void) {
    int localVar = 50;
    printf("Inside display() -> globalVar = %d, localVar = %d\n", globalVar, localVar);
}

int main(void) {
    printf("Inside main() -> globalVar = %d\n", globalVar);
    display();
    return 0;
}

Output:

Inside main() -> globalVar = 100
Inside display() -> globalVar = 100, localVar = 50

Line-by-line: globalVar is declared outside any function, so every function in the file can see it; localVar exists only inside display() and would cause a compile error if referenced from main(). Storage classes and full scope rules are covered in Chapter 3.

Advanced Example 1 — Case sensitivity and block scope shadowing

#include <stdio.h>

int count = 5;

int main(void) {
    int Count = 10;
    int count2 = 15;

    {
        int count = 99;
        printf("Inner block count = %d\n", count);
    }

    printf("Global count = %d\n", count);
    printf("Count = %d\n", Count);
    printf("count2 = %d\n", count2);

    return 0;
}

Output:

Inner block count = 99
Global count = 5
Count = 10
count2 = 15

Line-by-line: count and Count are different identifiers because C is case-sensitive; inside the { } block, a new count is declared that shadows (temporarily hides) the global count — only within that block. Once the block ends, count refers to the global variable again.

Advanced Example 2 — Common compile-time errors with identifiers and constants

These two programs are intentionally broken to show real compiler errors you will eventually hit.

Error case A — modifying a const variable:

#include <stdio.h>

int main(void) {
    const int MAX = 10;
    MAX = 20;
    printf("%d\n", MAX);
    return 0;
}

Actual GCC error:

ex10_const_error.c: In function 'main':
ex10_const_error.c:5:9: error: assignment of read-only variable 'MAX'
    5 |     MAX = 20;
      |         ^

Error case B — using a keyword as an identifier:

#include <stdio.h>

int main(void) {
    int float = 10;
    printf("%d\n", float);
    return 0;
}

Actual GCC error:

ex11_keyword_error.c: In function 'main':
ex11_keyword_error.c:4:9: error: two or more data types in declaration specifiers
    4 |     int float = 10;
      |         ^~~~~
ex11_keyword_error.c:4:15: error: expected identifier or '(' before '=' token
    4 |     int float = 10;
      |               ^

Why this matters: const is a compile-time contract, not just documentation — the compiler actively rejects any code path that reassigns it. Keywords are so reserved that the compiler doesn't even see float as "a bad variable name" — it sees "the start of a type," which is why the error message talks about "two or more data types" rather than "invalid identifier."

2.7 Common Mistakes (Chapter 2)

  • Trying to reassign a const variable.
  • Using a keyword as a variable name.
  • Forgetting that identifiers are case-sensitive (Total and total are different variables).
  • Using an uninitialized variable and assuming it starts at 0 — its value is indeterminate ("garbage") until you assign one.
  • Confusing #define (no type, no scope, pure substitution) with const (typed, scoped, real memory).

2.8 Interview Questions (Chapter 2)

Q1: What is the difference between a token and a keyword? A token is any smallest meaningful unit the compiler recognizes (which includes keywords, identifiers, constants, operators, and punctuation); a keyword is just one specific category of token — a reserved word with a fixed meaning.

Q2: Can you use a keyword as a variable name? Why or why not? No — keywords are reserved by the compiler grammar itself, so using one as an identifier causes a syntax error, as shown in Advanced Example 2.

Q3: What's the real difference between const and #define? const creates a typed, scoped, compiler-checked, debuggable variable; #define performs blind text substitution before compilation even begins, with no type safety and no scope.

Q4: What value does an uninitialized local variable hold in C? An indeterminate ("garbage") value — whatever bits happened to already be at that memory address. C does not automatically zero out local variables (unlike global/static variables, which are zero-initialized by default).

Q5: Is C case-sensitive? Yes — Age, age, and AGE are three completely distinct identifiers.

2.9 Practice Questions (Chapter 2)

  1. Write a program that declares a const double for the value of gravity (9.8) and uses it to compute weight from a given mass.
  2. Predict the output of a program where a variable is redeclared inside a nested block with a different value, then print it both inside and outside the block.
  3. List three valid and three invalid identifier names of your own, and explain why each invalid one fails.
  4. What is the output of printf("%zu\n", sizeof(int)); on your own machine? Compile and check — is it the same as this chapter's result?

2.10 Best Practices (Chapter 2)

⚠️ Warning: Never rely on the "leftover" value of an uninitialized variable — always initialize before use.

💡 Tip: Prefer const over #define for typed constants in modern C — you get type checking and debugger visibility for free.

  • Use UPPER_CASE naming for macro constants (#define MAX_SIZE 100) so they're visually distinct from ordinary variables.
  • Give variables descriptive names (studentAge, not x) once programs grow past trivial examples.
  • Declare variables close to where they're first used, not all at the top of a long function.

Chapter 2 Summary

Every C program is a stream of tokens: keywords, identifiers, constants, strings, operators, and punctuation. Identifiers name the things you create and must follow strict rules (start with a letter/underscore, no keywords, case-sensitive). Constants can be defined as typed const variables or as untyped #define macros — they behave similarly when read but are processed completely differently under the hood. Variables are named, typed memory locations whose values can change; each has both an address and a size that can be inspected directly.
